# M4 讲解卡　结束画面、快速重开、打包发布

## 一、这一单元做了什么

游戏结束时画面变暗，按原因显示不同标题（撞墙／咬到自己／撞到障碍物），并给出本局得分与最高分；
**按 R 立刻开新的一局**，不用关窗口；`mvn package` 能打出一个可以双击运行的 jar，并发布到 GitHub Release。

**验收标准**：`mvn test` 全绿；故意撞死后按 R 能重开，分数从 0 重新开始；`java -jar target/java-snake-1.0.0.jar`
能直接打开游戏；GitHub 的 Releases 页面有 v1.0.0 和可下载的 jar。

## 二、知识点 1：跨线程不要直接改状态，要"立旗子"

重开是按键触发的，而按键回调运行在 **EDT**（事件分发线程）上；游戏状态却只允许在 **游戏线程** 上修改。
如果直接在按键回调里调 `game.reset()`，就会有两个线程同时读改同一份状态。

本项目用的办法是"立旗子"：

```
按键回调（EDT）：  restartRequested = true;      // 只是立个旗子
游戏循环（游戏线程）： if (restartRequested) { restartRequested = false; game.reset(); }
```

`restartRequested` 是 `volatile`，保证两条线程都能立刻看见变化。
这和 M2 里"按键先入队、移动时才生效"是同一个思路：**谁拥有状态，谁才改状态；其他人只能提请求。**

## 三、知识点 2：重开就是把状态推回开局

看 `SnakeGame.startNewRound()`：把方向、状态、分数、步数、蓄水计数器、速度、输入队列、
蛇、障碍物、食物全部重设一遍。构造器和 `reset()` 都调用它——**一份初始化代码，两处入口**。

如果重开时漏掉任何一项，就会出现"重开之后速度还是上一局的"这类怪 bug。
检查清单的做法是：凡是"会变"的字段，都要在这里出现一次。

## 四、知识点 3：打包成一个能双击的 jar

`pom.xml` 里配了 `maven-jar-plugin`：

```
<archive><manifest><mainClass>com.example.snake.Main</mainClass></manifest></archive>
```

它做的事就是往 jar 里塞一个 `META-INF/MANIFEST.MF`，里面写一行 `Main-Class: com.example.snake.Main`。
有了这一行，`java -jar xxx.jar` 才知道该从哪个类开始执行；双击 jar 也是同理。

**注意**：本项目零第三方依赖，所以一个 jar 就够了。如果将来引了 Jackson 之类的库，
就必须用 shade 插件做"胖 jar"，否则运行时会报 `NoClassDefFoundError`。

## 五、知识点 4：Release 是给玩家的，git 仓库是给开发者的

`target/` 目录被 `.gitignore` 排除，所以 jar 不会进 git 历史（二进制文件进版本库是坏味道，
每次重新打包都会产生一个巨大的新版本）。

正确做法是把它作为**Release 附件**发布：玩家从 Releases 页面下载 jar 双击就能玩，
开发者 clone 仓库跑 `mvn package` 也能得到同样的东西。

## 六、代码怎么读

1. `GamePanel.updateGame()` —— 旗子怎么被消费
2. `GamePanel` 的按键回调 —— 旗子怎么被立起来，以及为什么 R 只在死掉之后才生效
3. `SnakeGame.startNewRound()` —— 重开要重置哪些东西
4. `pom.xml` 的 `maven-jar-plugin` 段

## 七、动手改造点

1. 把 R 键改成"任何时候都能重开"，想想这样有什么风险（会不会误触）。想清楚再改。
2. 让结束画面也显示"活了多少秒"：需要记录开局时间，并且写测试。
3. 给 jar 加上版本号显示：`java -jar xxx.jar --version` 打印 `pom.xml` 里的版本。
   这需要读 MANIFEST 或写一个常量，两个方案都试一试。
